# zxporter

![Type: application](https://img.shields.io/badge/Type-application-informational?style=flat-square)

A Helm chart for DevZero ZXPorter - Kubernetes resource monitoring and optimization

zxporter is the DevZero cluster agent. It watches the cluster's Kubernetes
resources and reports them to the DevZero control plane (dakr). It bundles the
`zxporter-nodemon` DaemonSet as a subchart; configure it under the
`zxporter-nodemon` key, or through `global.*` for values both charts share.

Every object carries `app.kubernetes.io/part-of: dz-platform` and a
`devzero.io/component` label naming its chart, from the shared
`devzero-common` library. Pod templates and selectors do not carry them.

To pull from a private registry, set `global.imageRegistry` (the `dz-platform`
umbrella sets it for every component). It replaces the registry host of the
controller image (and of the CRD-adoption hook's `kubectl` image) and keeps
the path, tag and digest:
`public.ecr.aws/devzeroinc/zxporter:<tag>` becomes
`<global.imageRegistry>/devzeroinc/zxporter:<tag>`. The value may carry a
path prefix (`harbor.example/devzero`). `global.imagePullSecrets` is merged
with `imagePullSecrets` on the controller pod; both take names or
`{name: ...}` objects.

The chart vendors its dependencies into `charts/`, which is not committed.
From a source checkout, run `make helm-deps` (or `helm dependency build` on
the chart) before installing or rendering it.

## GitOps and reinstalls

For GitOps or IaC installs, pass `zxporter.clusterToken` or `zxporter.existingSecret` so no Helm run can drop the token. With a PAT, zxporter re-attaches to its cluster by the kube-system namespace UID after a reinstall. Set `zxporter.clusterId` only to pin an install to a specific cluster.

zxporter keeps its cluster token in the Secret `devzero-zxporter-token` (or the ConfigMap, with `useSecretForToken=false`). If that token is lost, for example after `helm uninstall`, zxporter registers again with the PAT and DevZero re-attaches the same cluster by its kube-system namespace UID. The token is rotated by that re-registration, and the other DevZero operators reload it from the Secret. `zxporter.clusterId` applies only at registration, when no token is stored; to move an existing install to another cluster, delete `devzero-zxporter-token` before restarting zxporter.

## CRDs

The `collectionpolicies.devzero.io` CRD ships in `crds/`, which Helm installs
on the first install and never upgrades. A pre-install/pre-upgrade hook
(`crdAdoption`) adopts it into the release, so that a later release can render
it from `templates/` and upgrade it in place. Do not skip the release that
adopts it: an install that never ran the hook fails the upgrade that moves the
CRD. With `crdAdoption.enabled=false`, adopt it by hand before that upgrade:

```sh
kubectl label crd collectionpolicies.devzero.io --overwrite app.kubernetes.io/managed-by=Helm
kubectl annotate crd collectionpolicies.devzero.io --overwrite \
  meta.helm.sh/release-name=<release> meta.helm.sh/release-namespace=<namespace> \
  helm.sh/resource-policy=keep
```

`helm.sh/resource-policy: keep` means `helm uninstall` leaves the CRD and every
CollectionPolicy in it; delete the CRD by hand for a full cleanup.
